# Local vs Production: Side-by-Side Comparison

## Overview

This document compares your LOCAL development setup with the PRODUCTION setup for Railway + Vercel.

---

## Frontend URLs

### Local Development
```
Browser: http://localhost:5173 (Vite dev server)
API calls to: http://localhost:8000
File: No .env file needed (defaults to localhost)
```

### Production (Vercel)
```
Browser: https://ccs-portal.vercel.app (Vercel hosted)
API calls to: https://your-app.railway.app
File: .env.production with VITE_API_URL
```

---

## Backend URLs

### Local Development
```
URL: http://localhost:8000
Started by: php artisan serve
Database: localhost:3306 (your machine)
Debug: APP_DEBUG=true (see full errors)
Environment: APP_ENV=local
File: .env (local config)
```

### Production (Railway)
```
URL: https://your-app.railway.app
Started by: Docker container (Railway manages)
Database: railway.railway.internal:3306 (Railway MySQL)
Debug: APP_DEBUG=false (hide errors from users)
Environment: APP_ENV=production
File: Environment variables in Railway dashboard
```

---

## CORS Middleware

### Local Development
```php
$allowedOrigins = [
    'http://localhost:3000',
    'http://localhost:5173',
    'http://127.0.0.1:3000',
    'http://127.0.0.1:5173',
];
```

**Why**: Allows React dev servers and local testing

### Production (Railway)
```php
$allowedOrigins = [
    'http://localhost:3000',      // Keep for dev
    'http://localhost:5173',      // Keep for dev
    'http://127.0.0.1:3000',      // Keep for dev
    'http://127.0.0.1:5173',      // Keep for dev
    'https://ccs-portal.vercel.app',  // Add Vercel domain
    env('FRONTEND_URL', ''),           // Add env var support
];
```

**Why**: Allow Vercel frontend + environment flexibility

## Frontend Configuration

### Local Development
```
File: src/services/api.js

const API_URL = import.meta.env.VITE_API_URL || 'http://localhost:8000'
const API_BASE_PATH = import.meta.env.VITE_API_BASE_PATH || '/api'

// Falls back to localhost:8000 because no .env.production
Result: http://localhost:8000/api
```

### Production (Vercel)
```
File: frontend/.env.production

VITE_API_URL=https://your-app.railway.app
VITE_API_BASE_PATH=/api

In src/services/api.js (same code):
const API_URL = import.meta.env.VITE_API_URL || 'http://localhost:8000'
const API_BASE_PATH = import.meta.env.VITE_API_BASE_PATH || '/api'

// Now uses: https://your-app.railway.app/api
Result: https://your-app.railway.app/api
```

## Database Connection

### Local Development
```
Connection: Direct connection to MySQL on your machine
Host: 127.0.0.1 (your computer)
Port: 3306 (standard MySQL port)
Username: root
Password: (usually empty or your password)
Database: ccs_profiling_system

Access from: Your terminal/IDE
Backup: Manual or local backup service
```

### Production (Railway)
```
Connection: Through Railway's secure network
Host: railway.railway.internal (Railway's internal network)
Port: 3306
Username: Auto-generated by Railway
Password: Auto-generated by Railway (very secure)
Database: Auto-created by Railway

Access from: Only Railway backend container
Backup: Railway handles automatic backups
Connection pooling: Managed by Railway
```

## Authentication Flow

### Local Development
```
Browser opens: http://localhost:5173
         ↓
User types credentials
         ↓
Frontend sends POST to: http://localhost:8000/api/auth/login
(No CORS issue because both are localhost)
         ↓
Backend checks: .env with APP_DEBUG=true (verbose errors)
         ↓
Returns token: Stored in localStorage
         ↓
Future requests include: Authorization: Bearer {token}
         ↓
Backend validates in development mode (debug output shown)
```

### Production (Vercel/Railway)
```
Browser opens: https://ccs-portal.vercel.app
         ↓
User types credentials
         ↓
Frontend sends POST to: https://your-app.railway.app/api/auth/login
(Different domains - CORS check happens)
         ↓
CORS middleware checks:
  - Origin header matches FRONTEND_URL? ✓
  - If not, request blocked ✗
         ↓
Backend checks: Environment variables with APP_DEBUG=false (hide errors)
         ↓
Returns token: Stored in localStorage
         ↓
Future requests include: Authorization: Bearer {token}
         ↓
Backend validates in production mode (no debug info leaked)
```

## SSL/TLS (HTTPS)

### Local Development
```
Browser: http:// (not encrypted)
Backend: http:// (not encrypted)
Reason: Development, no sensitive data
Risk: None (localhost is local only)
```

### Production
```
Browser: https:// (encrypted by Vercel)
Backend: https:// (encrypted by Railway)
Reason: Protect user data in transit
Risk: Would be security issue to use http://
```

## Error Handling

### Local Development
```
Backend error occurs
         ↓
APP_DEBUG=true
         ↓
Full error page with:
  - Stack trace
  - Line numbers
  - Variable contents
  - Database queries
         ↓
Sent to browser for debugging
```

### Production
```
Backend error occurs
         ↓
APP_DEBUG=false
         ↓
Generic "500 Server Error" shown to user
         ↓
Full details logged to file (Railway logs)
         ↓
Admin can see logs in Railway dashboard
         ↓
But user doesn't see sensitive info
```

## Deployment Process

### Local Development
```
You code → You test → Done (on your machine)

No deployment needed - already "deployed" to your machine
```

### Production
```
You code → You push to GitHub
         ↓
Railway detects change (GitHub webhook)
         ↓
Railway pulls your code
         ↓
Railway runs: composer install
         ↓
Railway runs: npm install (if needed)
         ↓
Railway builds Docker image
         ↓
Railway runs: php artisan migrate --force
         ↓
Railway starts: Laravel server
         ↓
Now available at: https://your-app.railway.app
         ↓
Takes 3-10 minutes total
```

## Troubleshooting

### Local Development Issues
```
Problem: Frontend can't connect to backend
Solution: 
  1. Is Laravel running? (check php artisan serve running)
  2. Is port 8000 correct?
  3. Check browser console for errors
  4. Restart Laravel

Problem: Database connection error
Solution:
  1. Is MySQL running? (check Services in Windows)
  2. Are credentials in .env correct?
  3. Restart MySQL
  4. Run: php artisan migrate
```

### Production Issues
```
Problem: Frontend can't connect to backend
Solution:
  1. Check Railway logs (look for "Laravel Application Started")
  2. Verify FRONTEND_URL in Railway environment
  3. Check CORS middleware has your Vercel domain
  4. Redeploy on Railway

Problem: Database connection error
Solution:
  1. Check Railway MySQL service status (green?)
  2. Check database credentials in Railway variables
  3. Run: php artisan migrate:status in Railway logs
  4. Redeploy
```

## Summary

### What Changed:
- Frontend now points to Railway URL instead of localhost
- Backend CORS allows Vercel domain instead of just localhost
- Database is managed by Railway instead of local MySQL
- Debug mode is off to protect sensitive information
- Everything runs on HTTPS for security

### What Stayed The Same:
- All your code works exactly as-is
- All API endpoints function identically
- All authentication logic unchanged
- All database queries work the same way
- Frontend code doesn't need major changes

### Why These Changes:
- **HTTPS**: Protect user data in transit
- **CORS**: Prevent security issues with cross-domain requests
- **DEBUG=false**: Prevent info leakage in errors
- **Environment variables**: Flexibility without changing code
- **Managed database**: Better security, backups, reliability

---

**Bottom line**: Your codebase is production-ready with minimal changes! 🚀
